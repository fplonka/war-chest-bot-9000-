# v5_fast16_s1_gate

We were testing the first fast-GEMM build in a real training gate. It used the demonstrably stronger six-minute checkpoint from `v5_lane_whale_25m_learning` as its initializer, then still ran the requested five-minute Greedy value warmup before five minutes of ReBeL. The engine combined one-transfer table uploads, retained lane buffers, preallocated wave tables, card-wide routing for the rare giant tail, and cuBLAS FP16 internal operands with FP32 accumulation and output.

The run completed cleanly. It produced 236,621 ReBeL solves and 946,176 optimizer rows, leaving only 308 rows of debt. There were zero drops and zero exact CPU fallbacks, with 2,224 node-cap fallbacks and 525 lane-isolated whale routes. The final rate including a long drain was 762.1 balanced solves/s; the last report before admission stopped was 837/s. The drain pushed the process 10.6 seconds past its nominal budget, which matters to the formal golden metric but not to the user's preferred sustained-rate reading. This still does not meet 1,200/s.

The opening rate reached 1,605/s and then fell as the fresh game pool aged. The first games finished about 62 seconds after the ReBeL transition, so the decline is not caused by waiting many minutes for any terminal data. This stronger initializer made a harder workload than the prior gate: target standard deviation reached about 0.38 instead of about 0.28 at the comparable point. Because the checkpoint changed, the 762 versus 700 gate comparison is not a clean speed A/B. The frozen identical tape is clean: fast-FP16 GEMMs measured 643.7/s versus 587.2/s in precise FP32, a 9.6% gain.

Fast mode kept all probabilities finite and normalized and passed the exact zero-network oracle. Before the fast-mode error budgets were made explicit, 12 of 14 GPU tests passed; the two failures were CPU last-bit comparisons on random weights, with a maximum strategy difference of 0.025 and a root-value relative error around 0.04%. Precise mode passed all 14 tests. The earlier ladder evaluated with fast mode and still showed the six-minute checkpoint beating Greedy 26--3 and its initializer 24--2, so learning and play remain coherent under the production arithmetic.

During ReBeL, approximate average GPU utilization was 61% on GPU 0 and 65% on GPU 1; peak memory was 17,313 MiB and 18,763 MiB. The run predates the local experiment that stores the static head residual in FP16.
