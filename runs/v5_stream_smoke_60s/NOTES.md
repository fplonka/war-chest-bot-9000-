# Continuous trainer smoke test

We were checking that the new live GPU training path works as one system: generation continues while the optimizer consumes replay rows, updated weights are published back to both GPUs, optimizer work remains tied exactly to generated solves, and shutdown drains already-submitted solves without running past the fixed one-minute deadline. This was a functional smoke test from the published architecture-probe checkpoint, not a speed comparison.

The streaming path completed cleanly. It counted 44,399 solves, trained 177,152 rows with 444 rows of remaining debt (less than one 1,024-row batch), and published weights ten times. Five unusually large solves took the dedicated large-job path; none fell back to the CPU and no solve was dropped. Admission stopped at 40.4 seconds, pending work and optimizer debt drained by 50.1 seconds, and the process waited to the exact 60-second denominator with no overrun. All 3,456 unfinished games were deliberately marked censored at shutdown. The reported 738 balanced solves/s includes four optimizer rows per solve and the reserved drain time, so it is not the generation-throughput gate.

The smoke did find one checkpoint-only bug: because the whole run was shorter than the normal snapshot de-duplication window, the final snapshot label was put on the unchanged initial checkpoint instead of saving the trained weights. The stream and its accounting were unaffected. The trainer was changed immediately afterward so an `init` checkpoint is never reused as `final`; this run's `snap_00.pt` should therefore be read as the initial checkpoint despite the old manifest label.

At this point the project was using the direct two-card CUDA stream, 36 CPU workers with 96 games each, bounded replay backpressure, immutable versioned GPU weights with old versions pruned once no queued solve needs them, and the 384-wide value network. Fast GPU matrix multiplication was allowed to differ slightly from the CPU oracle; confidence came from the CUDA wave tests, finite-result checks, and the training invariants above rather than bitwise equality.
